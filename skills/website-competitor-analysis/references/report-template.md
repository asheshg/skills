# Assessment deck

## Finding selection

Before any deck export, present the verified findings by framework with a stable finding ID, a short title and the screen or journey. Use the evidence ID and original pin number together for visual findings (for example, E01-2), and the recorded test-log ID for non-visual findings. Keep these IDs stable when assigning pins or slide numbers for the export. Ask whether to include all verified findings or only the IDs they choose. Wait for an explicit selection before generating a file. When there are no verified findings, ask whether to create a coverage-only deck.

Keep the audit record complete. Include only the selected findings in the presentation, including its pins, evidence rows, callouts, recommendations and notes. Screen labels and pin numbers can be assigned for the deck, but retain the source IDs in the export map. Summaries may show verified aggregate test counts and coverage for the scoped audit. Where findings are filtered, identify the summaries as audit-wide and the deck as a selection. Keep individual unselected findings out of the summaries. Omit empty evidence slides and update the contents after selection.

Apply this reference only to presentation output. Use verified findings from the audit record and retain the evidence IDs in the slide notes or export map. Include the sections for selected frameworks and populate the contents from the actual slides. For the combined workflow, follow the Tata CLiQ website section for structure and tables. For PowerPoint, open the supplied presentation template as the source presentation. Start with the closest original example slide for each role and replace content in place. Keep its master and layout visible, with the original font family, type hierarchy, palette, margins, table style and image treatment. Use neutral presentation titles and filenames. If a template includes a source-branded title, footer or wordmark, replace that visible branding with the requested owner name or omit it from the presentation. Adapt only the space needed for the audit content and remove unused example slides. Compare the rendered deck with the corresponding originals before delivery.

1. Cover with the audited website name and domain, assessment title and date.
2. Table of contents on the next slide. Use the template's contents example. List the sections actually present in their final order with accurate slide numbers or ranges.
3. Assessment parameters. When Core UX is selected, reproduce both complete [Tata CLiQ tables](core-ux-framework.md#canonical-parameters) with all 32 rows, in order. Keep the four original headers, wording and grouped area cells. Use the template's table treatment, a wide table and readable body text. Use the two source splits as the baseline and add a continuation only if needed for legibility.
4. Workflow evidence in journey order. Highlight the current stage and place paired desktop/mobile screenshots beside one shared table. Use **No**, **Pain Point**, **Description**, **Experience Assessment Parameter** in that order. Use short, concrete descriptions and cite applicable parameter codes in the final column. Keep device and source details with the evidence. Keep WCAG criteria and deceptive-pattern taxonomy IDs in their summaries or linked test records. Numbered pins match the rows. Skip screens with no findings. If one capture is blocked or outside scope, state the gap and use the verified capture. For requested competitor evidence, use **No**, **What’s working**, **Why**.
5. **Accessibility Pass Rate**. Put the pass rate, coverage and supporting explanation on the left, with an annotated image of an observed accessibility issue on the right when a capture can substantiate it. Give the image a caption with its criterion and evidence reference. If the issue is non-visual, use a faithful capture of the relevant test output or DOM evidence. Keep the scope, status counts and methods visible, and compute the figures using the WCAG reference.
6. **Deceptive-Pattern Summary**. Use **What we checked**, **What we found** and **Scope limits** as bold headings. Keep body text distinct from the headings. Cover the decisions checked, human-confirmed findings and linked remedies, and describe what remains untested. Include supporting images when they substantiate or clarify the finding or choice, such as captures of two states in a pricing flow.
7. Conditional competitor benchmark. Benchmark only a supported weakness on the same task and stage. End with the last substantive slide and omit the standalone name or wordmark slide.

For every audit image, use a thin template-compatible neutral stroke and subtle drop shadow so it remains distinguishable from the canvas. Use square corners on screenshots and keep the effects outside the evidence. Use visible light-grey borders on all table cells, including internal rules.

Before placing any claim in the deck, verify it against the underlying evidence for the exact page, state and scope. Check the actual interaction or measurement when a screenshot alone cannot substantiate the claim. Recalculate figures from the test records and carry the same verified wording into headings, summaries, captions and recommendations. Leave unsupported claims out of the deck. Disclose observed risks and test limits with the evidence that supports those narrower statements. Keep the test records with the manifest. Keep pending deceptive-pattern signals in the test record. The summary reports the verified findings and the limits of the review. Inspect every rendered slide for readable type, complete tables, visible sources and accurate pins. Split dense evidence across existing template layouts and keep the workflow order and table headers.
